## 1. 공통
- 비즈메시지 센터 통계 API는 https 프로토콜을 사용하며, GET method를 사용합니다. response는 JSON형태로 전달됩니다.
- 비즈메시지 센터 통계 API는 블룸에이아이에 등록된 고객사에 대해 허용된 IP로 접근할 수 있는 제한적으로 오픈된 서비스를 제공합니다.
- 블룸에이아이 운영 담당자를 통해 요청 시 필요한 `AgentKey`를 발급 받아야 한다. (요청 시 header에 추가)
- 카카오 비즈메시지 통계(발송·유효 읽음·클릭)를 조회합니다. 통계 값은 카카오가 집계한 값을 그대로 전달하며, `data` 내부는 가공하지 않습니다.
- 모든 API는 `sender_key`(발신프로필 키)가 필수이며, 한 번에 1개만 조회할 수 있습니다. `sender_key`를 2개 이상 넣으면 400, `4002`(유효한 발신프로필을 찾을 수 없음)가 전달됩니다.
- 일별 통계는 하루(`date`) 단위로 조회합니다. 기간 조회가 필요하면 날짜별로 호출합니다.
- `product`에는 `alimtalk`(알림톡) 또는 `brandmessage`(브랜드 메시지)를 넣습니다. 친구톡 통계는 제공하지 않습니다.
- 실시간 통계는 제공하지 않습니다. 조회 가능 시점은 [<1.5. 조회 시점과 조회 모드(mode)>](#15-조회-시점과-조회-모드mode)를 참고 바랍니다.

### 1.2. RESPONSE SAMPLE
##### [성공]
```json
{
    "code": "200",
    "data": [
        {
            "mode": "FINAL",
            "list": [
                ... // 통계 목록
            ]
        }
    ]
}
```

- `data`는 요소 1개짜리 list이며, 그 안에 조회 모드(`mode`)와 통계 목록(`list`)이 있습니다.
- 조회 데이터가 없으면 `"code": "200"`과 빈 `list`가 전달됩니다.

##### [잘못된 요청 또는 에러]
```json
{
    "code": "4000",
    "message": "입력값 오류 발생",
    "detail": "올바른 날짜를 입력해주세요. (yyyyMMdd)"
}
```

| 키      | 타입 | 설명                                                    |
|---------|------|---------------------------------------------------------|
| code    | text | 결과 코드 **[<1.4. 코드 정의 에서 확인 가능>](#14-코드-정의)** |
| message | text | 오류 내용                                               |
| detail  | text | 상세 사유 (값이 없으면 응답에서 생략)                    |
- 필수값이 없으면 카카오 통계 API를 호출하지 않고 400, `LS0001`이 전달됩니다. 누락된 항목은 `detail`에 표시되며, 여러 개면 모두 표시됩니다.
```json
{
    "code": "LS0001",
    "message": "잘못된 요청 JSON 또는 Querystring",
    "detail": "sender_key는 필수입니다."
}
```

### 1.3. HTTP 상태 코드
통계 API는 HTTP 상태 코드로 성공·실패를 구분합니다.

| HTTP | 설명                                                                                               |
|------|--------------------------------------------------------------------------------------------------|
| 200  | 정상 응답                                                                                            |
| 400  | 요청 정보가 잘못됨 (LS0001, 4000, 4002 등)                                                                |
| 401  | 요청 권한이 없음 (LS0002)                                                                               |
| 404  | 존재하지 않는 경로 (응답 본문 없음)                                                                            |
| 500  | 통계 집계 상태 오류 (5000, 5001, 5002), 카카오 시스템 오류 (9999) 또는 내부 오류 (LS9999). 5000·5001·5002는 집계 이후 다시 조회 |
| 502  | 카카오 통계 API 호출 실패 (LS0102)                                                                        |
| 504  | 카카오 통계 API 호출 타임아웃 (LS0101). 카카오가 30초 안에 응답하지 않으면 전달되므로, 요청 타임아웃은 30초보다 길게 설정 바랍니다.              |

### 1.4. 코드 정의
| code   | 설명                                                                     |
|--------|--------------------------------------------------------------------------|
| 200    | 요청 성공                                                                |
| 4000   | 입력값 오류 발생                                                         |
| 4001   | 유효한 허브파트너를 찾을 수 없음                                         |
| 4002   | 유효한 발신프로필을 찾을 수 없음                                         |
| 4004   | 요청한 리소스를 찾을 수 없음                                             |
| 5000   | 아직 통계 데이터가 집계되지 않음 (집계 이후 조회 가능)                   |
| 5001   | 통계 집계에 실패 (재집계 이후 조회 가능)                                 |
| 5002   | 통계 집계 중 (집계 이후 조회 가능)                                       |
| 9999   | 시스템에 문제가 발생하여 담당자가 확인하고 있는 경우                     |
| LS0001 | 잘못된 요청 JSON 또는 Querystring (누락 항목은 `detail`에 표시)          |
| LS0002 | 유효하지 않은 AgentKey                                                   |
| LS0101 | 카카오 통계 API 호출 타임아웃                                            |
| LS0102 | 카카오 통계 API 호출 실패                                                |
| LS9999 | 블룸에이아이 API 내부 시스템 에러                                        |

- LS로 시작하는 코드는 블룸에이아이 통계 API의 오류이고, 나머지는 카카오 통계 API의 오류입니다. `9999`와 `LS9999`는 다른 코드입니다.

### 1.5. 조회 시점과 조회 모드(mode)
| 통계                  | 조회 가능 시점                            | mode 위치             | mode 값                                                                |
|-----------------------|-------------------------------------------|-----------------------|------------------------------------------------------------------------|
| 발송 일별             | 전날 수집된 데이터를 매일 오전 7시경 제공 | `data[0].mode`        | CHARGE_PENDING : D+1 과금 미확정 / FINAL : D+2 확정 데이터             |
| 유효 읽음·클릭 일별   | 전날 수집된 데이터를 매일 오전 7시경 제공 | `data[0].mode`        | FINAL : D+1 확정 데이터                                                |
| 발송 시간별           | 발송 시간의 H+2 이후                      | `data[0].mode`        | CHARGE_PENDING : H+24 이전 과금 미확정 / FINAL : H+24 이후 확정 데이터 |
| 유효 읽음·클릭 시간별 | 집계 시간(반응 시간)의 H+2 이후           | `data[0].mode`        | PREVIEW : H+2 ~ H+3 / FINAL : H+4 이후 확정 데이터                     |
| 시간 범위별           | 집계 시간(반응 시간)의 H+2 이후           | `data[0].list[].mode` | PREVIEW : H+2 ~ H+3 / FINAL : H+4 이후 확정 데이터                     |

- 일별 통계는 전날 데이터를 매일 일배치로 처리해 오전 7시경 제공합니다. (카카오 내부 상황에 따라 변경될 수 있음)
- 알림톡 발송 일별 통계는 ACK 타임아웃 반영으로 D+1에 최초 제공되고, D+2에 확정됩니다.
- 일별 통계를 당일 날짜로 조회하면 `5000`(아직 통계 데이터가 집계되지 않음)이 전달됩니다.
- 알림톡 발송 시간별 통계는 ACK 최대 H+24 타임아웃을 반영해 집계 실행시간을 포함한 H+26에 확정 집계됩니다.
- 확정(FINAL) 전에 조회한 데이터는 이후에 바뀔 수 있습니다.

### 1.6. 유의사항
- 유효 읽음·클릭 일별 통계는 경과일(`elapsed_day`) 0 ~ 2로 나눠 제공됩니다. 조회일의 총량은 0 ~ 2를 각각 조회해 합산합니다. D+3 이후 데이터는 제공되지 않습니다.
- 유효 읽음·클릭 통계는 2024년 4월 1일부터 제공되며, 발송일 기준 발송 성공이 10건 이하이면 해당 일자분은 시간별·일별 모두 제공되지 않습니다.
- 유효 읽음·클릭 시간별 통계의 발송일(`send_date`)은 집계일(`date`)로부터 최대 -2일까지 조회할 수 있습니다. (예: `date=20240403`이면 `send_date=20240401~20240403`)
- 템플릿 통계는 `template_code`와 `group_tag_key` 중 하나를 사용합니다. 둘을 함께 넣으면 400, `4000`(입력값 오류 발생)이 전달됩니다.
- 브랜드 메시지 자유형은 그룹태그를 사용한 경우에만 제공됩니다.
- 발송 클릭 통계(일별·시간별·시간 범위별)는 브랜드 메시지만 제공합니다. 알림톡 클릭은 템플릿 클릭 통계로 조회합니다.
- 시간 범위별 통계(4.3, 4.5, 5.3, 5.5)는 조회 범위(`start_date_time` ~ `end_date_time`)가 넓을수록 응답이 늦어지며, 30초를 넘으면 504, `LS0101`이 전달됩니다.
- 일별 통계의 조회 날짜가 월 확정(거래명세서) 이전이면 참고용 자료이며, 확정 과금 기준 데이터와 차이가 있을 수 있습니다.
- 유효 읽음수는 메시지 말풍선이 실제로 그려진 시점을 기준으로 집계됩니다.
- 유효 읽음수는 동일 사용자가 동일 메시지를 같은 기기에서 여러 번 확인하면 중복 집계되지 않습니다. 같은 메시지의 클릭은 중복 집계합니다.
- 유효 읽음수는 동일 사용자가 모바일, PC, 태블릿 등 서로 다른 기기에서 확인하면 기기별로 집계될 수 있습니다. 이 경우 발송 성공수보다 유효 읽음수가 많을 수 있습니다.

### 1.7. 호출 한도
- 블룸에이아이 통계 API는 초당 500건까지 호출할 수 있습니다. 초과한 요청은 HTTP 429(응답 본문 없음)로 거절되며, 1초 후 다시 호출하시면 됩니다. 일 호출 한도는 없습니다.
- 확정(FINAL) 데이터는 변하지 않으므로 같은 조건을 반복 조회하지 않고, 시간 범위별 통계는 조회 범위를 좁게 나누어 호출하시면 응답이 안정적입니다.

## 2. 일별 통계
### 2.1. 발송 일별 통계
발신프로필 기준 일별 발송 집계를 조회합니다.
- 전날 데이터를 매일 오전 7시경 제공하며, `mode`는 CHARGE_PENDING(D+1, 과금 미확정) / FINAL(D+2 확정)입니다. 당일 날짜로 조회하면 `5000`이 전달됩니다. ([<1.5. 조회 시점과 조회 모드(mode)>](#15-조회-시점과-조회-모드mode) 참고)

##### [Request]
**GET** /api/v1/stat/{product}

##### [Header]
| 키       | 타입 | 필수 | 설명                                                        |
|----------|------|------|-------------------------------------------------------------|
| agentKey | text | Y    | `사전에 블룸에이아이 운영 담당자를 통해 전달 받은 AgentKey` |

##### [Parameter]
| 키         | 타입     | 필수 | 설명                                                    |
|------------|----------|------|---------------------------------------------------------|
| product    | text     | Y    | (Path) 조회 상품. alimtalk : 알림톡, brandmessage : 브랜드 메시지 |
| date       | text     | Y    | 조회일 (yyyyMMdd)                                       |
| sender_key | text(40) | Y    | 발신프로필 키 (1개)                                     |
| page       | number   | N    | 조회 페이지 번호 (default : 1)                          |
| count      | number   | N    | 한 페이지당 크기 (default : 500, max : 10,000)          |

##### [Response]
응답 바디는 JSON 객체로 아래 값을 참고해 주세요.

| 키    | -    | 타입   | 설명                                           |
|------|------|------|----------------------------------------------|
| code |      | text | 결과 코드 **[<1.4. 코드 정의 에서 확인 가능>](#14-코드-정의)** |
| data |      | list | 조회 결과 (요소 1개)                                |
|      | mode | text | 조회 모드 (CHARGE_PENDING, FINAL)                |
|      | list | list | [발송 집계 항목](#61-발송-집계-항목) 참고                  |

##### [Example]
**GET** /api/v1/stat/alimtalk?date=20260922&sender_key={sender_key}&page=1&count=500
```json
{
    "code": "200",
    "data": [
        {
            "mode": "FINAL",
            "list": [
                {
                    "date": "20260922",
                    "sender_key": "{sender_key}",
                    "uuid": "@uuid",
                    "message_type": "AI",
                    "receive_user_type": "PhoneNumber",
                    "charged_success_count": 1,
                    "free_contract_success_count": 0,
                    "free_template_success_count": 0,
                    "unknown_request_count": 0,
                    "valid_fail_count": 0,
                    "invalid_fail_count": 0
                }
            ]
        }
    ]
}
```

### 2.2. 유효 읽음 일별 통계

##### [Header]
| 키       | 타입 | 필수 | 설명                                                        |
|----------|------|------|-------------------------------------------------------------|
| agentKey | text | Y    | `사전에 블룸에이아이 운영 담당자를 통해 전달 받은 AgentKey` |

##### [Parameter]
| 키          | 타입     | 필수 | 설명                                                    |
|-------------|----------|------|---------------------------------------------------------|

| elapsed_day | number   | Y    | 조회일 기준 경과일수 (0 ~ 2). 0이면 조회일 당일, 2이면 D+2 |
| sender_key  | text(40) | Y    | 발신프로필 키 (1개)                                     |
| page        | number   | N    | 조회 페이지 번호 (default : 1)                          |
| count       | number   | N    | 한 페이지당 크기 (default : 500, max : 10,000)          |

##### [Response]
응답 바디는 JSON 객체로 아래 값을 참고해 주세요.

| 키    | -    | 타입   | 설명                                           |
|------|------|------|----------------------------------------------|

| data |      | list | 조회 결과 (요소 1개)                                |
|      | mode | text | 조회 모드 (FINAL)                                |
|      | list | list | [유효 읽음 항목](#62-유효-읽음-항목) 참고                  |

**GET** /api/v1/stat/alimtalk/read?date=20260922&elapsed_day=0&sender_key={sender_key}&page=1&count=500

        {
            "mode": "FINAL",
            "list": [
                {
                    "date": "20260922",
                    "sender_key": "{sender_key}",
                    "uuid": "@uuid",
                    "message_type": "AT",
